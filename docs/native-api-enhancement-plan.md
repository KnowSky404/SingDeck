# Native API enhancement plan

This plan takes SingDeck from its v0.8.1 dashboard baseline to a native sing-box control, diagnostics, and observability workspace. Each phase has its own acceptance gate. The [roadmap](roadmap.md) tracks phase status, the [capability matrix](native-api-capabilities.md) records the RPC contract, and the [verification record](verification.md) records executed checks.

## Baseline audit

The starting point was `main` at `dfb16e822ffe0c38830d5b52d8d0cd0dc4b34f67`. On 2026-11-27, GitHub reported `main` as the default branch, v0.8.1 as the latest release, and no open PRs or issues. Recent changes hardened remembered credentials, improved native URL-test batching, and refreshed groups after a service restart. The vendored v1.14.0 descriptor exposes 42 RPCs. The baseline client exposes 14, of which 12 have dashboard consumers. `GetClashModeStatus` and `SetClashMode` are SDK-only at this baseline. [Release and history](https://github.com/KnowSky404/SingDeck/releases/tag/v0.8.1)

| Area | Current foundation | Gaps to address |
| --- | --- | --- |
| Transport | Generated Proto, binary gRPC-Web, Bearer metadata, no cookies or redirects, and unary deadlines | Extend the typed adapter and use upstream implementation evidence for runtime semantics. The existing browser adapter supports unary and server-streaming RPCs. |
| State and performance | One abortable `InstanceSession`, periodic status watchdog, independent stream retry loops, 100 ms update batching, bounded traffic, logs and connection records, and paginated connections | The workspace provider publishes the full snapshot. Measure subscriber rerenders, snapshot copies and rendering costs at scale. Establish performance baselines before changing store or render strategy. |
| Information architecture | Lazy hash routes and a compact responsive shell. Groups already have independent group and node layouts with server-confirmed selection | Preserve existing `#/proxies` bookmarks as the page evolves into Outbounds. Place diagnostics and instance-scoped features under shared navigation. Use availability to keep unconfigured native services out of primary navigation. |
| Browser trust and storage | Browser TLS, loopback-only HTTP, safe React log rendering, explicit demo, and an opt-in AES-GCM record bound to instance and endpoint | The remembered credential store has one `active` slot. Extend it only with migration and tab concurrency coverage. Treat remote labels, links, diagnostic output and files as untrusted. Same-origin scripts can use the stored key. |
| Verification | CLI checks, Chromium desktop and mobile emulation, and official v1.14.0 Linux integration | Add controlled real diagnostic fixtures, core restart and unavailable cases, plus Firefox, WebKit, deployment and workload measurements. Version-specific runtime evidence belongs in the verification record. |

The current upstream releases at the audit were stable v1.14.5 and prerelease v1.15.0-alpha.14. Both retained API version 4 and the pinned proto. The official v1.14.0 Linux amd64 build remains the reproducible test baseline. Source agreement alone leaves newer runtime behavior unverified. [Stable release](https://github.com/SagerNet/sing-box/releases/tag/v1.14.5) · [Prerelease](https://github.com/SagerNet/sing-box/releases/tag/v1.15.0-alpha.14) · [API compatibility](api-compatibility.md)

## Shared implementation decisions

- Keep the unmodified upstream proto and regenerate checked-in descriptors with the existing Buf script when the pinned contract changes. Use verified versions and actual runtime capabilities to determine availability. Keep ConnectRPC framing in the API adapter, lifecycle in the session, and view state in the feature UI.
- Keep the existing static build, built-in `/dashboard/`, relative assets, hash routing, and independent GitHub Pages deployment. Phase 1 uses the browser gRPC-Web adapter directly. Advanced transports require a separate feasibility check and may be optional where supported.
- Reserve browser connection headroom for interactive requests. Six long-lived HTTP/1.1 streams stalled a warning refresh in Chromium against the official loopback core. Connections and outbound inventory share a subscription slot by active view. Resubscribing to connections starts from a core snapshot. A core-initiated cancellation can trigger stream recovery while the session scope remains active.
- Reuse the Bun, strict TypeScript, React, Vite, Tailwind, shadcn/Radix, Lucide, Recharts, Vitest, and Playwright stack. Evaluate new dependencies by necessity, maintenance, size, license, and alternatives.
- Keep the existing English and Simplified Chinese, light/dark/system choices, semantic tokens, keyboard access, and responsive layouts. Each new surface needs loading, empty, unavailable, error, and disconnected behavior. Use measured layout and render performance on desktop, tablet and mobile.
- Keep production credentials in memory by default, report remote errors with fixed actionable messages, and preserve browser TLS and exact allowed origins. Use only native Service API data. The explicit demo uses the same client contract and clearly labeled simulated results.

## Phase 1 — Native Diagnostics

| Workstream | Deliverables and acceptance evidence |
| --- | --- |
| Capability registry | Model `unknown`, `supported`, `unavailable`, `error`, and `unsupported` per active instance and core lifetime. Distinguish unimplemented RPCs, missing or unconfigured resources, authentication failure, denied access and transient failures. Use read-only signals and the result of expressly requested operations. Reuse successful in-session evidence, refresh on core state changes or new sessions, and use capability state in controls and navigation. Verify that rendering and discovery never start tests or mutations. |
| Outbound inventory | Use `SubscribeOutbounds` beside `SubscribeGroups` for Groups and All Outbounds views. Show all advertised tags and reported types, including ungrouped entries. Do not infer endpoint metadata beyond what the core sends. Add tag search, protocol filter, list/cards, latency sorting and freshness, group membership and selected routes. Retain server-confirmed selection. Support selected and batch URL tests within upstream behavior, prevent overlapping work and cancel queued requests. Check real group selection, an ungrouped tag, fresh timestamps, and unknown or absent results. |
| Network quality | Run `StartNetworkQualityTest` only after an explicit action. Allow core default and reported outbound selection, duration, serial and HTTP/3 options, and an explicitly confirmed custom configuration URL. Show phase, elapsed time, download/upload capacity and RPM, idle latency, and reported accuracy. Preserve bounded live curves, final report, copy/export and comparison across outbounds. Use a test scope separate from monitoring. Check real frames, final and canceled streams, and interruption before completion. Explain data usage and that the path is from the core. |
| STUN / NAT | Run `StartSTUNTest` with the core default or an expressly confirmed server and the chosen outbound. Show phase, reachability, external address, latency, and independently reported NAT mapping/filtering when the server supports the behavior test. Display partial results explicitly and preserve copy and outbound comparison. Test a local UDP fixture for reachable/mapped/partial behavior, cancellation, and errors. NAT mapping and filtering use the upstream enums without inferring legacy NAT names or broader UDP metrics. |
| Configuration health | Use `GetDeprecatedWarnings` to display core/API versions, count and all reported fields. Provide manual refresh, restart refresh, urgency filters, and copy. Allow safe links to authoritative migration documentation. Verify the empty response in CLI attachment mode and warning fields in a daemon-managed fixture. The CLI-attached API has no collector, and a daemon read drains newly collected warnings. An empty response establishes only that the core reported no warnings. [Collector](https://github.com/SagerNet/sing-box/blob/v1.14.0/daemon/deprecated.go) · [Collector registration](https://github.com/SagerNet/sing-box/blob/v1.14.0/daemon/instance.go) |

Use a bounded in-memory comparison set initially. Local diagnostic history is optional and must use the instance and retention rules defined below if enabled. Never extrapolate capacity, quality or test success from a transport acknowledgement, a missing URL-test timestamp, or a stream that ends without a confirmed result.

## Phase 2 — Advanced Observability

| Workstream | Deliverables and acceptance evidence |
| --- | --- |
| Runtime monitor | Reuse status, service status, start time and version. Show memory, goroutines, inbound/outbound connections, current/cumulative traffic, uptime, lifecycle events, stream health and last update. Add short configurable windows and peak/average rates. Label browser-observed history, stale data, reconnection and restarts. Event streams can be quiet while healthy. Verify sample intervals, first samples, pause and restart without inventing CPU, disk, or host load metrics. |
| Connection inspector | Add native ID, endpoint, timestamps, counters/rates, rule, outbound chain and all available process fields to details. Compose network, IP version, inbound, outbound, protocol, domain, rule, process, user and state filters. Add quick reset, sorting, useful columns, safe copying and export. Trace the upstream order of routing fields before visualizing it. Link to the reported outbound and correlate logs only where data permits. Verify filtered batch close, single close and confirmed close-all without counting closed rows as blocked. |
| Traffic analytics | Aggregate observed upload/download for domain, process, inbound, outbound, rule, protocol, TCP/UDP, IP version and user. Add top values, shares, trends, window totals and CSV/JSON export. Define gaps and unknown groups. Prove snapshot, NEW/UPDATE/CLOSED, reset, restart and eviction handling with tests that preserve traffic totals and count a connection once. Keep persistence opt-in, bounded, removable and isolated if introduced. |
| Notifications | Subscribe to native events and preserve cancellation and source semantics. Label separate local events for service failures, API issues, warnings, diagnostics and failed selections. Add unread count, read/dismiss actions, bounded history, deduplication, severity/source filters and safe links. Desktop notification permission is optional and explicit. Verify native and local event lifecycles and instance isolation. |
| Clash Mode | Read modes and initial selection from `GetClashModeStatus`, observe `SubscribeClashMode`, and confirm `SetClashMode` through the subscription. Hide controls when unavailable. Verify a configured fixture, an absent controller, invalid modes and synchronization with a second client. These are native API calls. |
| Logs and groups | Evaluate `ClearLogs` separately from clearing local display, with a deliberate action for the core buffer. Improve ANSI search and exports under load. Evaluate `SetGroupExpand` persistence and retain local expansion as the default. Cover large logs and any opt-in cross-client behavior. |

## Phase 3 — Multi-instance Management

- Add instance create/edit/delete, labels/groups, ordering, favorites, default/recent selection, last connection, health and core/API version, with list/cards and a compact switcher. Keep one active instance initially.
- Give each instance its own client, capabilities, credentials, history and preferences. Abort old streams and diagnostics on replacement and guard delayed results. Verify rapid switches, React remounts and cross-tab changes.
- Migrate the single remembered slot to independently revocable, opt-in AES-GCM records. Keep instance ID and validated endpoint as binding data, demand revalidation after endpoint edits, and omit tokens from URLs, logs, exports and plaintext storage. Confirm interrupted migration, concurrent edits, forget-one and forget-all, including revocation after failed authentication.
- Evaluate an opt-in overview with tightly limited concurrency for health, version, memory, goroutines, traffic, connections and warning counts after single-instance switching passes.

## Phase 4 — Native Services

| Workstream | Deliverables and evidence gates |
| --- | --- |
| Tailscale | Start with configured endpoint status, self, peers and user groups, real exit-node state, search/filter, stream ping and exit-node changes with confirmation. Evaluate logout, certificate metadata and SSH separately. Keep private key material out of routine display and exports. Use only actual peer/path data. |
| Taildrop | Verify read-only inbox subscription, unread state, download stream, deletion and receive cancellation first. Confirm destructive actions and scope by endpoint and instance. Sanitize filenames, bound memory, and test partial transfer, size limits and cancellation. Sending depends on validated bidirectional transport. |
| OpenConnect and OpenVPN | Verify each endpoint status and actual challenge forms against configured services. Respect each protocol's response and cancellation semantics. Protect passwords, one-time codes, cookies and headers from storage, logs and export. Report unavailable flows when the browser cannot complete them safely. |
| USB/IP | Verify read-only service, device, descriptor, backend and status reporting. Device provider work requires verified bidirectional transport, browser hardware permissions and OS support, including permission denial and unplug cases. |
| Browser streaming research | Validate the official bridge against framing, metadata, Bearer authentication, cancellation, backpressure, errors, TLS, browsers and reverse proxies. The current gRPC-Web client cannot provide browser bidirectional support. A Chromium loopback proof against official v1.14.0 exchanged interleaved USB provider frames, confirmed Bearer authentication and completed a half-close using the official gRPC-WebSocket bridge. It used an absent service tag and no USB device. The bridge accepted a browser Origin excluded by HTTP CORS. Production use needs verification of Origin enforcement, TLS, proxy behavior, cancellation, flow control and browser support. Track SSH, Taildrop sending and device provision independently of read-only services. [Official bridge](https://github.com/SagerNet/sing-box/blob/v1.14.0/service/api/web_bridge_websocket.go) |

Capability state controls native service navigation. Service acceptance needs dedicated fixtures with the corresponding build, configuration, and where applicable hardware or authenticated test network.

## Phase 5 — Performance, Security and Stable Release

- Measure connection, log and outbound workloads at 1,000, 10,000 and higher records. Record environment, bundle size, first display, route change, long tasks, render time, memory and extended stability. Change batching, retry budgets, subscription granularity, pagination, virtualization or code splitting where measurements justify it. Use cancellable scopes and watchdogs appropriate to each stream.
- Verify Chromium, Firefox, WebKit and mobile across built-in hosting, independent static paths, Nginx/Caddy HTTPS, loopback and SSH tunnels. Include CORS, local network permission, certificate trust, browser storage and locks, clipboard, response buffering, idle open streams and reconnect. Test real deployment environments separately from local fixtures.
- Evaluate installability, custom workspace preferences, and retention controls after the base is stable. Any service worker must exclude credentials, private API responses, connection records, logs and authentication challenges from caches. Browser monitoring runs while the workspace can execute.
- Audit XSS, remote text and URL handling, credentials, CSP and cross-origin policy, files, challenge forms, IndexedDB, service worker caches, dependencies, CI permissions and licenses. Preserve license notices and the independent UI. Capture actual findings and remaining exposure in the verification record.

## Delivery gates

Each phase must be independently reviewable from current `origin/main`. Apply the risk, scoped local checks, CI, review and PRE gates in [AGENTS.md](../AGENTS.md). Phase acceptance covers the affected protocol, browser and negative paths using controlled fixtures and the pinned official binary as applicable. Label mock and official-core evidence separately. Record results against the tested head and base or integration SHA. Update CI when a new suite must run there. This initiative leaves PR merge, release publication and production deploy decisions to the maintainer.

Record the source audit, RPC capability changes, implementation and architecture decisions, UX and verification results, performance and security findings, open limitations and their causes, and branch/commit/PR in the delivery record. Update the English and Chinese READMEs, deployment and troubleshooting instructions, and changelog as features ship. Update the wiki when it can be maintained. Finish Phase 1 acceptance before beginning Phase 2 implementation. A transport or fixture blocker for a single capability stays scoped to that capability.
